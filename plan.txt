Phase 1 — Fix the foundation first 🔧

There is one architectural issue I would address before adding many new features.

1. Move chat history from global localStorage to user-scoped storage

Currently your chat history uses:

akshra_chat_history

and stores complete conversations in localStorage.

That means the history is browser/device-level, not truly account-level.

This creates an important scenario:

User A
→ logs in
→ has chats
→ logs out

User B
→ logs in on the same browser
→ can potentially encounter the same locally stored history.

Your UI says:

“Sign in to save and sync your conversations with Akshra Ai”

but the current implementation does not actually sync conversation history through MongoDB. The sidebar is consuming locally stored chats.

Better architecture
User
  ↓
Session
  ↓
MongoDB
  ├── User
  ├── Chat
  │    ├── title
  │    ├── model
  │    ├── messages
  │    ├── createdAt
  │    └── updatedAt
  │
  └── OTP

Then:

Browser
   ↓
POST /api/chats
   ↓
MongoDB

The sidebar becomes a real synchronized account feature.

This single change will make Akshra feel much more like a real SaaS product.

Phase 6 — Improve the authentication/security layer 🔐

The current authentication foundation is good, but before production scale I'd strengthen it.

OTP rate limiting

Currently the client has a 60-second resend countdown, but the server should independently enforce limits.

For example:

3 OTP requests / 15 minutes / email
10 verification attempts / 15 minutes

Otherwise a malicious client can simply bypass the UI timer.

Don't store OTP plaintext

Your MongoDB OTP record currently stores the OTP directly.

A production-grade approach is:

OTP
 ↓
hash
 ↓
MongoDB

Then compare the submitted OTP against the hash.

Session strategy

Your session is configured for roughly one year and /api/auth/me renews the cookie.

I'd consider separating:

short-lived access session
+
rotating refresh/session mechanism

with revocation capability for security-sensitive environments.
